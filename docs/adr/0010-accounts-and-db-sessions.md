# 0010. 계정과 DB 세션, 경로별 접근 정책 표

- 상태: 채택 (2026-10)
- 지키는 방법:
  - `AccessPolicyTest`: 모든 경로가 표에 있음, 운영 경로는 운영자만
  - `AuthServiceTest`: 해시만 저장, 재시작 후에도 로그아웃 유지, 비밀번호 변경 시 다른 세션 해지, 운영자 계정 만들기
  - `AuthControllerTest`: 로그인 지연, 로그인 실패 감사 상한·성공 기록의 직전 실패 수(QA-125)
  - `LoginFailureAuditTest`: 로그인 실패 감사 표본(1·5·2^k번째·한 시간에 한 번, 없는 계정 시간당 상한과 요약)
  - `ApiIntegrationTest`: 회원 403, 계정 존재를 드러내지 않음, 다른 출처 POST 403
  - `SessionFilterTest`
  - `PasswordPolicyTest`

## 배경

로그인은 비밀번호 하나(`APP_PASSWORD`)와 서명 토큰(JWT)이었습니다. 사용자가 한 명뿐이라 등급·권한을 나눌 수 없었고, 로그아웃한 토큰을 막는 목록이 메모리에 있어 재시작하면 사라졌습니다. 구독 모델([명세 B](../specs/2026-10-09-feature-spec.md))은 계정·등급·등급별 접근 제어가 전제입니다.

## 결정

1. **계정은 이메일 + 비밀번호입니다.**
   - 비밀번호는 Argon2id로 해시합니다(`spring-security-crypto` + BouncyCastle, Spring Security 전체는 들이지 않음).
   - 역할: `OWNER`·`MEMBER`. 등급: `FREE`·`PRO`. 운영자는 등급과 무관하게 모두 씁니다.
2. **세션은 DB에 둡니다.**
   - 쿠키에는 32바이트 무작위 토큰, DB(`user_sessions`)에는 그 SHA-256만 둡니다.
   - 로그아웃·비밀번호 변경·계정 삭제가 다음 요청부터 반영되고, 재시작해도 유지됩니다.
   - JWT와 `JWT_SECRET`은 없앴습니다.
3. **경로마다 누가 부를 수 있는지 표 하나**(`AccessPolicy`)에 빠짐없이 적습니다.
   - 기본값이 없어, 새 경로를 표에 넣지 않으면 빌드가 실패합니다.
   - 같은 경로 안의 범위 제한(무료는 최근 N건 등)은 서비스가 사용자 등급을 받아 처리합니다.
4. **사용자 정보(`CurrentUser`)는 `support`에 둡니다.** 세션 필터가 요청 속성에 넣습니다. ADR 0001 규칙 2 때문에 다른 기능의 컨트롤러가 `feature/auth` 타입을 쓸 수 없어서입니다.
5. **기존 사용 흐름을 잇습니다.**
   - 처음 기동할 때 계정이 없으면 `OWNER_EMAIL`·`APP_PASSWORD`로 운영자 계정(PRO)을 만듭니다.
   - 둘 중 하나라도 없거나 비밀번호가 공개된 옛 기본값이면 만들지 않고 로그로 안내합니다. 자리표시 이메일을 기본값으로 두지 않습니다.
   - 계정이 생긴 뒤에는 두 값을 읽지 않습니다.
6. **계정 존재를 드러내지 않습니다.** 없는 이메일도 가짜 해시와 비교해 같은 시간·같은 401을 냅니다.
7. **로그인 지연(`LoginThrottle`)의 키는 (접속 주소, 이메일)입니다.**
8. **가입·메일 인증·비밀번호 재설정은 SMTP 메일로 합니다**(`spring-boot-starter-mail`).
   - `MAIL_HOST`가 비면 그 기능만 꺼집니다(503, 로그인 화면은 링크를 숨김).
   - 가입·재설정 요청은 계정 존재와 무관하게 같은 응답입니다. 이미 있는 주소면 그 주인에게만 안내 메일을 보냅니다.
   - 링크 토큰은 SHA-256만 저장하고 한 번만 쓸 수 있습니다(인증 24시간·재설정 30분). 재설정하면 모든 세션을 끊습니다.
   - (주소·이메일)마다 시간당 5회로 제한합니다.
   - 계정 삭제는 비밀번호를 다시 확인하고 개인정보를 바로 지웁니다. 감사 기록은 사용자 번호만 비웁니다. 운영자 계정은 지울 수 없습니다.
   - 감사 기록은 1년 보존합니다(2026-10-11 결정). 6시간마다 도는 정기 작업이 1년 지난 기록을 지웁니다(`AuthService.purgeOldAuditLog`).
   - 로그인 실패는 표본만 남깁니다(QA-125, `LoginFailureAudit`). 로그인 없이 부를 수 있는 경로라 실패마다 한 행이면 1년 보존 기록을 인증 없이 끝없이 키울 수 있었습니다. 지연 키 (주소, 이메일)는 이메일만 바꾸면 새로 생기므로, 표본은 공격자가 새로 만들 수 없는 단위로 셉니다.
     - 있는 계정: 사용자 번호마다 연속 실패(주소가 달라도 한 묶음, 15분 조용하면 끝)의 1·5·8·16…번째와 공격이 이어지는 동안 한 시간에 한 번을 실패 수(`failures`)와 함께 남깁니다. 성공(`login.success`)과 메일 인증 전 성공(`login.unverified`)에는 직전 실패 수(`priorFailures`)를 붙입니다.
     - 없는 계정(형식이 아닌 이메일 포함): 전체를 한 묶음으로 한 시간에 30건까지 이메일과 함께 남깁니다. 넘친 개수는 5분마다 도는 정기 작업과 종료 때 `login.failure.suppressed` 한 줄(`count`·`from`·`to`·`limit`, 사용자 번호 없음)로 남깁니다. 있는 계정의 몫과 따로라 쓰레기 요청으로 노리는 계정의 실패를 지울 수 없습니다.
     - 접속 주소는 남기지 않습니다(명세 B10). 상태는 메모리에만 있어 재시작하면 새로 셉니다.
9. **다른 출처에서 온 상태 변경 요청은 막습니다.** POST·PUT·DELETE의 `Origin`이 CORS 허용 목록에 없으면 403입니다(SameSite에 더한 한 겹). Origin이 없는 요청(스크립트)은 통과시킵니다.

10. **등급(B3)은 두 층으로 나눕니다.**
    - **정책 표(경로 전체 PRO):** AI 리포트, 종목별 투자자 매매 이력, 13F 신규 매수 교집합, 구루 포트폴리오 위험
    - **서비스(같은 경로 안의 범위):** 판정 기록은 무료 최근 30건, 판정 성과는 무료 SPY만
    - 범위가 등급마다 다른 응답은 응답 캐시 키에 등급을 넣습니다.
    - AI 리포트는 유료 회원 하루(KST) `AI_DAILY_LIMIT`건(기본 20, V6 `usage_counters`, 조건부 UPSERT). 운영자는 한도가 없고, 엔진이 모두 실패하면 되돌립니다.
    - 결제 연동 전까지 등급은 운영자가 👥 사용자 관리에서 정합니다(명세 D4).

## 이유

- **DB 세션을 고른 이유:** 즉시 끊어야 할 일(로그아웃·비밀번호 변경·등급 변경·삭제)이 늘어납니다. 상태 없는 토큰으로 하려면 결국 서버에 차단 목록이 필요하고, 그러면 JWT의 장점(DB 조회 없음)이 사라집니다. 이 규모에서 요청마다 인덱스 조회 한 번은 비용이 아닙니다.
- **토큰을 해시로 저장하는 이유:** DB나 백업이 새어도 쿠키를 만들 수 없습니다.
- **정책 표에 기본값을 두지 않는 이유:** 새 경로가 조용히 "로그인한 누구나"로 열리면, 운영 기능이나 나중의 유료 기능이 의도치 않게 공개됩니다.

## 대안과 버린 이유

- **Spring Security 전체 도입:** 필터 체인·CSRF·세션 관리가 지금의 필터·쿠키 설계와 겹칩니다. 필요한 것은 해시뿐이라 crypto 모듈만 씁니다.
- **JWT 유지 + DB 차단 목록:** 차단 목록 조회가 결국 요청마다 생겨 두 방식의 복잡도를 모두 떠안습니다.
- **bcrypt:** 추가 의존성 없이 되지만, OWASP 권장 순위가 Argon2id 다음입니다. BouncyCastle 하나를 더하는 비용이 작습니다.
- **로그인 실패 표본을 지연 키 (주소, 이메일)마다 첫 실패·지연 진입만으로(QA-125):** 이메일만 바꾸면 키가 새로 생겨 상한이 되지 않고, 키에 접속 주소가 들어가며, 지연 기록이 꽉 찬 동안의 실패는 셀 수 없어 노리는 계정의 실패를 감사에서 지울 수 있습니다.
- **`OWNER_EMAIL`이 없으면 자리표시 이메일로 계정 만들기:** CLAUDE.md 규칙(자리표시 값을 코드 기본값으로 두지 않음)에 어긋납니다.

## 결과

- 새 테이블: V4 `users`·`user_sessions`·`audit_log`, V5 `email_tokens`.
- 새 경로: `POST /api/auth/logout-all`, `GET /api/auth/sessions`, `POST /api/auth/password`, `POST /api/auth/signup`·`verify`·`reset/request`·`reset/confirm`·`delete`.
- 화면: 로그인에 이메일 칸, 👤 내 계정(비밀번호 변경·로그인한 기기). 일반 회원에게는 운영 메뉴(저장소 상태·연결 테스트)와 수동 새로고침 버튼을 숨깁니다. 막는 것은 백엔드입니다.
- **운영 이전:** 기존 `.env`에 `OWNER_EMAIL` 한 줄을 더하면 지금 비밀번호로 그대로 로그인합니다.
