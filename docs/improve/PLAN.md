## 1. 진행 방식

- 브랜치: `claude/improve-2026-10`. 이름은 프로젝트 규칙(`claude/<주제>-YYYY-MM`)을 따릅니다. 붙여 주신 지시의
  `improve/YYYYMMDD`와는 다르고, 프로젝트 CLAUDE.md를 우선했습니다.
- 결함마다 커밋 두 개입니다. **`test(QA-###)` 재현 테스트**(수정 전 코드에서 실패하는 것을 확인한 뒤 `@Disabled`·xfail·`it.fails`로 커밋)
  → **`fix(QA-###)` 근본 원인 수정**(표시 해제). 이것도 프로젝트 규칙입니다. 붙여 주신 지시는 '한 커밋'이지만, 수정 전 실패 출력은
  지시대로 PROGRESS.md에 남깁니다.
- 옮기는 커밋(`refactor`)과 고치는 커밋을 섞지 않습니다. 의존성(`chore(deps)`)·문서(`docs`)도 따로 커밋합니다.
- 모든 커밋이 `make test`를 통과해야 합니다. 백엔드는 CI와 같은 JDK 21로 돌립니다.
- 작업은 영역별로 나눠 병렬로 합니다. 각자 별도 작업 폴더(worktree)와 **별도 테스트 DB**(`macrodash_<영역>_test`)를 씁니다.
  끝나면 한 브랜치에 차례로 합치고, 합친 뒤 커밋마다 테스트를 다시 돌립니다.
- 운영 DB(`macrodash`)·운영 스택·실제 외부 API는 쓰지 않습니다. 외부 응답은 고정본(fixture)과 목으로 대신합니다.
  AWS는 조회만 하고 배포하지 않습니다.
- **push와 `main` 병합은 하지 않습니다.** 프로젝트 CLAUDE.md는 끝나면 병합·push하라고 하지만, 이번 지시는 '내가 한다'입니다.
  그래서 끝에 여쭙습니다.

| KRX 연말 휴장일이 주말일 때(직전 평일 휴장 여부) | 공식 규정을 확인하지 못했습니다. 다음 해당 해가 2028년이라 지금은 영향이 없습니다 |

## 7. 그대로 둔 것과 이유 (검토했고 문제없음)

- **인증·세션**: 32바이트 무작위 토큰을 쓰고 DB에는 SHA-256만 둡니다. 로그인마다 새 토큰이라 세션 고정이 불가능합니다.
  쿠키는 HttpOnly·SameSite=Strict, AWS에서는 Secure입니다. 역할·등급은 요청마다 다시 읽습니다. 계정 존재 여부의 시간 차는
  같은 Argon2 경로라 없습니다.
- **다른 사용자 접근(IDOR)**: 알림 규칙·알림함·세션의 모든 쿼리가 `user_id = ?`로 거르고, 사용자는 필터가 넣은 값만 씁니다.
- **SQL 주입**: 모든 쿼리가 바인딩을 씁니다. IN 목록도 자리표시만 이어 붙입니다.
- **오류 응답**: `include-message: never`이고 상태별 고정 문구만 내보냅니다. 원인은 로그에만 남습니다.
- **데모 열람 경계**: 토큰은 상수 시간으로 비교합니다. GET 밖은 `POST /api/ai/report` 하나만 열립니다. 합성 사용자는 FK가 막습니다.
- **AI 비용 한도·되돌림(QA-021)**: 데모 공용 풀은 `synchronized`, 회원 한도는 조건부 UPSERT라 동시 요청에도 넘지 않습니다.
  AI 출력은 React 텍스트 노드로만 그리므로 XSS가 없습니다.
- **DB 연결 점유**: 트랜잭션 없는 문장 단위라 AI 대기(최대 110초) 동안 연결(AWS 4개)을 쥐지 않습니다.
- **계산 쪽 null·NaN**: 분모 0은 모두 막혀 있고, NaN·무한대가 JSON으로 새는 경로가 없습니다. 판정 성과의 발표 시점 재현은
  발표 시각을 하나씩 대조했고 미래 정보를 쓰지 않습니다.
- **수집기 저장 계층**: 교체 쓰기·하루치 트랜잭션·마이그레이션 잠금·NaN 처리·종목코드 앞자리 0·이어받기 기한(QA-056)은 맞습니다.
- **수집기 API**: 토큰 상수 시간 비교, 빈 토큰이면 기동 거부, Host 허용 목록, 교차 출처 차단, 입력 허용 목록, 고정 베이스 URL이라
  SSRF 여지가 없습니다.
- **의존성 취약점**: `constraints.txt` 고정판 57개에 pip-audit 0건, `npm audit --omit=dev` 0건입니다. Node 24·PostgreSQL 16/18·
  Temurin 21은 지원 기간 안입니다. Python 3.11은 2027-10 종료라 지난 결정대로 다음 라운드에서 봅니다.
- **비밀값**: 추적 파일에 키 모양 문자열이 0건이고, `.env`가 이력에 들어간 적이 없습니다.
- **구조**: 화면의 raw `fetch`는 `lib/api.ts` 한 곳뿐입니다. 컨트롤러는 서비스만 부릅니다. 계산(`analytics`)은 스프링·JSON을
  모릅니다. 테스트가 이를 막고 있어 목표 구조를 새로 적용할 곳이 없습니다.
