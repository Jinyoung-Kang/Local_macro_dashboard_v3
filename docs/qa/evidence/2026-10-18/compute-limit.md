## 결론

- 목표(서비스 전체가 멈추지 않음)는 이룸: 모든 판·모든 RATE에서 health가 항상 200이고 5xx·시간 초과가 0. 수정 전에는
  RATE 50에서 health가 88% 실패하고 로그인이 18초 걸렸음.
- 첫 수정만으로는 재시작 직후 같은 키 요청 45건이 각자 자리 대기열에 서서 대기열 상한(32)을 넘겨 429가 났음 → 같은 키
  묶기로 해결(9회 중 1회만 429 5건, AWS 근사 자리 1).
- 남은 한계: 초당 50개 공격 중에는 자주 읽는 키도 다시 계산할 때 공격 요청 뒤에 줄을 서서 4–8%가 429를 받고 p95가 1초
  안팎으로 오름. 화면은 이미 받은 값을 두고 '새로 읽지 못함'만 표시함. 없애려면 '바쁠 때 직전 값 돌려주기'가 필요하지만
  `ageSeconds`·60초 약속이 흐려져 보류함([decisions.md](../../../decisions.md) 2026-10-19).
- AWS 자리 수: 자동(=1)이면 vCPU 하나가 이웃 프로젝트·health 몫으로 남고(공격 중 CPU 183%), 재시작 직후 몰림에서 3회 중 1회
  429 5건. 2로 올리면 몰림 429는 0이지만 공격 중 CPU 205%로 두 vCPU를 다 씀. 기본은 자동(=1)으로 두고, 반영 뒤 거절 WARN
  로그를 보고 `COMPUTE_MAX_CONCURRENT`로 조정.
