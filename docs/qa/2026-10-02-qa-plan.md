## 2. 검증 환경 — 운영 스택을 건드리지 않는다

운영 스택(`local_macro_dashboard_v3`, 포트 3000/8080/8000/5432, DB `macrodash`)은 **읽지도 쓰지도 않습니다.**
대신 같은 코드로 **QA 스택**을 따로 띄웁니다.

| 항목 | QA 스택 |
|---|---|
| compose 프로젝트 | `macrodash_qa` (`COMPOSE_PROJECT_NAME`) — 볼륨 `macrodash_qa_postgres-data`, 운영 볼륨과 분리 |
| 포트 | 화면 13000 · API 18080 · 수집기 18000 · DB 15432 (127.0.0.1) |
| 비밀값 | `.env.qa` — 이 세션에서 **새로 만든** 비밀번호·토큰. 운영 `.env`의 값은 쓰지 않음. 외부 API 키는 전부 비움 |
| 데이터 | 운영 백업(`backups/macrodash-20261002-180440.sql`)을 QA DB에 **복원** — 복원 절차 자체가 검증 항목(ADR 0003) |
| 외부 호출 | 수집기 스케줄러 끔. 수집기의 외부 요청은 **차단 프록시**(`HTTPS_PROXY` → 로컬 블랙홀)로 막아 유료·한도 API를 한 번도 부르지 않음. 느림·먹통 시험은 같은 프록시를 지연 모드로 |
| 정리 | 끝나면 `scripts/qa/qa-stack.sh down`으로 컨테이너·볼륨 삭제(운영 볼륨은 손대지 않음) |

외부 소스의 **실제 응답**이 바뀌는 경우(Daum·Naver 표 구조, FRED 형식 등)는 이 환경에서 검증할 수 없어
"검증하지 못한 부분"에 적습니다. 소스별 파서는 저장된 응답·목(mock)으로 검증합니다.

## 3. 우선순위와 항목

심각도: **S1** 치명(보안 침해·데이터 손실·전면 불능) · **S2** 높음(틀린 숫자·주요 기능 불능·긴 멈춤) ·
**S3** 중간(기능 결함·UX 장애) · **S4** 낮음(표시·접근성 경미). 치명 결함은 발견 즉시 보고하고 계속 진행.

### P0. 보안 (가장 먼저)
| 검증 | 방법 |
|---|---|
| 인증 누락 | 60개 백엔드 경로를 쿠키 없이 전부 호출 → 모두 401인지. 경로 변형(`//api`, `/api/health/..`, `;`, 대소문자, 인코딩, HEAD/OPTIONS/PUT) |
| 인가(IDOR) | 단일 사용자 앱이라 사용자 간 경계는 없음. 대신 **수집기 API가 호스트 밖·토큰 없이** 닿는지, 백엔드를 거쳐 수집기 제어(`/api/status/run/{task}`·`refresh`)가 세션 없이 되는지 |
| 인젝션 | 문자열 파라미터 전부(`cik`·`codes`·`symbol`·`seriesId`·`task`·`obsDate`·`q`·`ids`·`name`)에 SQL·경로·포맷 조작 문자열. 백엔드는 JDBC 바인딩, 수집기는 psycopg 바인딩인지 코드 대조 + 실제 호출 |
| CSRF·XSS·헤더 | Origin 위조 요청의 CORS 응답, 쿠키 속성, `nosniff`·`no-store`·`X-Frame-Options`·CSP, 13F 종목명 같은 외부 문자열이 화면에서 HTML로 해석되는지(`<img onerror>` 삽입 데이터로 렌더 확인) |
| 비밀값 노출 | 오류 응답·`/api/status`·`/api/status/public-apis`·AI 오류 문구·컨테이너 로그에 키·토큰·계정 ID가 있는지(QA 스택에 가짜 키를 넣고 로그를 grep) |
| 로그인 보호 | 대입 지연(5회 뒤 1초/건·429·Retry-After), 본문 4KB 상한, JWT 기본 비밀로 토큰 위조 시도, 세션 만료 |
| 의존성 | `pip-audit`, `npm audit`, Maven 직접 의존성의 GitHub Advisory 조회, EOL 일정(Python 3.11·Node 22·PG 16·Spring Boot 4.1·Next 15·React 18) |

### P0. 데이터 손실·신뢰성
| 검증 | 방법 |
|---|---|
| 백업·복원 | QA DB에 운영 백업 복원 → 행 수·최신 날짜 대조 → 다시 백업 → 두 백업의 데이터 동일성. 깨진 파일(끝 표시 없음)로 복원 시도 → 거부되는지 |

| 작업 도중 재시작 | 지연 프록시로 수집을 느리게 만든 뒤 수집기를 강제 종료 → `timeseries`·`observations`·`snapshots`에 **반쪽 데이터**가 남는지(트랜잭션 경계) |

| 외부 느림·먹통 | 프록시 지연 30초/무응답 → 백엔드 응답 시간 상한(화면이 기다리지 않는지), 스케줄러 다른 태스크 진행, pykrx 차단기 |

## 4. 산출물과 규칙
- `scripts/qa/`: `qa-stack.sh`(up/restore/down), `docker-compose.qa.yml`(포트·프록시·스케줄러 off),
  `blackhole-proxy.py`(차단·지연 모드), `auth-probe.sh`(60경로 인증 점검), `fuzz-api.py`(경계값·조작 입력),
  `k6/*.js`(부하), `axe-run.js`(접근성), `lighthouse.sh`.
- 재현 테스트: 기존 테스트 체계에 추가(백엔드 JUnit·수집기 pytest·화면 vitest). 이름에 `QA-###`.
- 커밋: 결함마다 `test(QA-###)`(실패 시험) → `fix(QA-###)`(근본 원인) 둘로 나눔. 각 커밋은 `make test` 통과.
  테스트·스크립트·데이터 외의 운영 코드 변경은 **확인된 결함의 근본 원인 수정**에 한함(리팩터·기능 추가 없음).
- 끝내기 전 별도 에이전트가 결함 목록의 재현 절차대로 **다시 재현**하고 심각도만 확인.
- 증거: 명령과 출력·로그·테스트 결과를 `docs/qa/evidence/`에 텍스트로. 내장 브라우저 스크린샷은 파일로
  저장되지 않아 콘솔·네트워크 기록(텍스트)과 재현 절차로 대신합니다.
